## 描述缺陷

`package.json` 的 `main` 曾指向 `src/index.ts`（TypeScript 源文件），Node.js 无法直接解析 TS 语法，启动时报 `SyntaxError`。改用 esbuild 编译后，TypeScript 装饰器（Typert 的 `@Remote`）采用 legacy 语义输出，导致运行时 `context.name` 为 `undefined`，二次报错。最终切换为 Babel 标准装饰器编译链解决。

## 复现步骤

1. 使 `main` / `exports["."]` 指向 `.ts` 源文件或含装饰器的未正确编译产物
2. 启动 `dsh web` 加载插件
3. 看到如下报错：`SyntaxError: Invalid or unexpected token at compileSourceTextModule`
4. 改用 esbuild（`experimentalDecorators: true`）编译后，Typert 校验报 `Remote decorators require a public instance method with a string name`
5. 编译时亦报 `Static class blocks are not enabled`（Babel 7 需显式启用）

## 预期行为

插件源码被正确编译为可运行的 JS，`@Remote` 标准装饰器按 ECMAScript 标准语义生效，`context.name` 可正确取得方法名，`dsh web` 正常加载。

## 实际行为

- 直接加载 `.ts`：`SyntaxError: Invalid or unexpected token`
- esbuild legacy 装饰器：`TypeError: typert-protocol: Remote decorators require a public instance method with a string name`
- Babel 7 未配静态块插件：`Static class blocks are not enabled. Please add @babel/plugin-transform-class-static-block`

## 环境信息

- dsh 版本：`dsh --version`（全局 dsh CLI + dsh-app-boot）
- 插件版本：`dsh-session-tag-manage` v0.1.0
- Node.js：v24.13.1
- 构建工具：Babel（原 esbuild）

## 日志 / 报错

```
SyntaxError: Invalid or unexpected token
    at compileSourceTextModule (node:internal/modules/esm/utils:318:16)
```

```
TypeError: typert-protocol: Remote decorators require a public instance method with a string name
```

## 根因与解决

- **根因**：
  1. standalone 插件无 DSH 框架内置的 TS 转译器，必须预先编译为 JS；
  2. TypeScript legacy 装饰器（`experimentalDecorators`）与 Typert 期望的 TC39 标准装饰器语义不同，`context.name` 为 `undefined`；
  3. Babel 7 需显式启用 `@babel/plugin-transform-class-static-block`。
- **解决**：迁移到 Babel 标准装饰器编译链，并在**保留源码 `.ts` 导入后缀**的同时于产物层改写为 `.js`。

| 文件 | 变更 |
|---|---|
| [babel.config.cjs](file:///c:/global-user-data/ai-workspace/dsh-session-tag-manage/babel.config.cjs) | 新增：`@babel/preset-typescript` + `@babel/plugin-proposal-decorators`（`version: '2023-11'` 标准装饰器）+ `@babel/plugin-transform-class-static-block` + 自研 `rewrite-ts-imports` 插件 |
| [scripts/rewrite-ts-imports.cjs](file:///c:/global-user-data/ai-workspace/dsh-session-tag-manage/scripts/rewrite-ts-imports.cjs) | 新增：产物层将 `import ... from './x.ts'` 改写为 `./x.js` |
| [tsconfig.json](file:///c:/global-user-data/ai-workspace/dsh-session-tag-manage/tsconfig.json) | 移除 `experimentalDecorators` / `emitDecoratorMetadata`；保留 `allowImportingTsExtensions`（源码 `import ... .ts`） |
| [package.json](file:///c:/global-user-data/ai-workspace/dsh-session-tag-manage/package.json) | `main: src/index.ts` → `dist/index.js`；新增 `build: babel ... --ignore "src/client/**"`；增加 Babel 相关 devDependencies |

```javascript
// babel.config.cjs 关键片段
['@babel/plugin-proposal-decorators', { version: '2023-11' }],
'@babel/plugin-transform-class-static-block',
'@babel/plugin-transform-class-properties',
require('./scripts/rewrite-ts-imports.cjs'),
```

```bash
# 编译（产物 dist/ 下 .js，客户端单独走 esbuild 打包）
pnpm build
```

## 其他补充

- 源码继续使用 `.ts` 后缀导入以满足 `allowImportingTsExtensions` 类型检查，`.js` 改写完全发生在 Babel 产物层。
- 验证装饰器时需使用真实 `Context` 实例，避免 `Cannot read properties of undefined (reading 'provide')` 这类假 Context 构造失败干扰定位。
